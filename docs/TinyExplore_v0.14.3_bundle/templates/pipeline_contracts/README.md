# Pipeline contracts 1.0.0
These artifacts define review/generation mechanics, not application requirements. The root workflow declares their authority. The human task alone defines application behavior; the immutable selected pair defines supported core interfaces.

## IN / OUT review
Read root entry.json Design.validation_policy. Each consumer independently validates actual input before work, even if the producer reported passed. Required semantic review is not a hash check. In particular resolve the selected Level0 delivered_shape and compare all affected dispatch branches with actual callback topic strings. Keep producer and local subscription topic separate; derive delivered_topic from the selected contract, never a universal hardcoded rule.

Reports follow review.schema.json. Use exact subject SHA-256 and JSON pointers. Write external reports and index Runtime.reviews; never insert an archive's own SHA into itself. Preserve the exact task-manifest snapshot before updating its runtime index. Required findings block affected work. Review passed is not VERIFIED. ZIP-only agents can complete generation and hand over UNVERIFIED candidates for another tester; AEP is optional.

## Event actions 1.1.0
New or changed event_actions in a new package1 use event_actions.schema.json, referenced by its new target generation policy1.1.0. Materialize the schema and these semantics under device/common/contracts/ in new package1 and declare exact paths/hashes so standalone package1 is complete. Replace contradictory old tag-only/success-only generation-policy text for the affected scope; retain baseline bytes as history, not simultaneous authority. This is a declarative behavior contract, not runtime reflection or a methods/fields/collections specification. Empty actions are valid for a foundation. Do not migrate untouched module contracts merely to adopt this schema; do not mutate the baseline. Existing changed event_actions must be explicitly projected to the versioned format in Model-First and reviewed before Code-First.

The complete event_actions.example.json is non-authoritative teaching data: do not copy its colors, IDs, names, payloads or actions into a task unless that task requires them. It illustrates required command success, optional arm failure continuation, guarded cleanup, exact WDG_CONFIRM accepted matching, event-argument dispatch and preserved context.

- actions run in declared order only after trigger and guard match. Unmatched/malformed input is trace-only.
- trigger.producer and trigger.topic describe the producer/local topic; delivered_topic is the resolved callback value. dispatch selects an exact parsed filter tag or exact event argument value; event_argument requires index.
- all steps are synchronous command-contract invocations. Same-module calls may use only the registered handler shortcut with Publish-equivalent arguments/results. Cross-module calls use Publish. Never use private timer/subscription state.
- `${event_ctx:X8}` means uppercase 8-digit incoming ctx; `${args[n]}` preserves validated original text; `${peer}` means an explicitly bound task value. These are declarative substitutions, not arbitrary executable expressions. Undeclared placeholders block affected projection.
- Steps are ordered. when=null means no extra prerequisite; when=<step-id> requires that preceding step's success. IDs are unique within an action, including finally steps. References must resolve to preceding steps. required=true requires on_failure=stop; required=false allows continue. A stop exits normal steps but still performs an entered finally scope. Exceptions are failures and are traced.
- success prefix/exact checks are ordinal on a nonnull command result. Synchronous Publish succeeds when a matching response exists; local shortcut checks its single response. An explicit confirmation must use exact accepted, never generic +OK. Ignored/null/error responses must not cause business actions.
- finally.enter_after names a successful preceding main step that enters cleanup, or null for no cleanup. Run cleanup on normal exit/failure/throw after entry, without masking original errors. Cleanup is best effort; all cleanup steps must use required=false/on_failure=continue so each is attempted.
- Trace ctx, guards, command outcomes and accepted/ignored decisions. Queue admission is not physical TX/peer reception. No new generic WDG behavior or application pending table is implied.

JSON Schema checks structure, not semantics. review_event_actions.py is a narrowly scoped reference check for delivered topics, step references and cleanup, using the supplied Level0 DDR; unsupported profiles block that helper rather than guessing. It does not replace the full semantic review or validate every command. Review additionally enforces unique IDs, valid references, resolved substitutions, cleanup rules, ownership, supported commands/args and delivered-topic compatibility. fingerprint.py reproduces the current pair's documented fingerprint profile and makes no edits. If another pair declares a different algorithm/profile, use that contract, not this helper by assumption.

## Versions and history
Version a changed module contract independently of the package family: SemVer major for incompatible changes, minor for backward-compatible capability additions, patch for compatible corrections/clarifications. Preserve an unchanged module version/fingerprint; relabeling a package alone changes neither. Record before/after versions, fingerprint and reason. Source-only repairs follow the authoritative contract; do not invent an API version change.

Current acceptance tests are indexed as active, with scope/Role prerequisites. Prior scripts, reports and integrated maintenance remain historical evidence and must not be automatically executed. In a new output relocate or mark superseded test entries and retire only integrated active replacement entries; original input ZIPs remain exact. No AEP runtime/grammar is implied by package generation. `---` is an AppLog/RKB marker; `###` is a worker expression only under an explicitly supplied Role that defines it. Never send worker expressions to the device. Optional prompts require real role-defined branching; answering No must skip the commands, not merely label them optional. Without a supplied Role produce an acceptance plan, not an invented executable dialect.

## Patch integration
Read root Design.patch_integration_policy. Default is carry all active patches, not integrate. Only current human `Integrate patch: all.`, `Integrate patch: <revision>.` or `Integrate patch: <artifact path>.` authorizes that integration. Evaluate all affected DDR/source/binding/dependency paths. Ambiguous/conflicting selection preserves affected scope with a finding; it does not drop the patch or block unrelated valid work. Unusable integrity/effective placement still blocks affected work.

Record Runtime.patch_integrations, provenance and actual before/after hashes. PLANNED is not INTEGRATED. Retire only successfully reconciled active scope, preserving original patch/evidence history. A partial integration of a whole-file replacement requires a safe explicit residual/rebase or preservation; never silently lose remaining changes. No automatic VERIFIED promotion.
