# Examples · choose a task

Examples demonstrate how human intent becomes a Model-First declaration and then a Code-First increment. Slides, diagrams and DDR excerpts are teaching material, not hidden agent inputs.

## Package0 · application tasks
Start here follows the four-step workflow. Power ON establishes startup; Pinging adds SEND; Pinging with ACK uses SEND_ACK; Pinging with ACK and Watchdog uses public WDG/WDG_CONFIRM and a 15000 ms deadline. Later examples derive their actual delta from the selected pair, not from example number.

Create package0 is editable: replace/extend human requirements, title, family and version. Include a sequence diagram only when useful. Export requires an explicitly selected valid package12 pair. Select from the active microLAR or Browse your own ZIP; a browse choice is not imported into the repository.

The exported ZIP contains task, selected baseline, current generic workflows and required support/overlay artifacts. It does not contain every community artifact. Attach it to an AI with “Instructions inside”. Model-First is a separate phase and must return package1 plus handoff and stop. Explicitly authorize Code-First next. Semantic IN/OUT reviews are required at both stages; current task and paired interfaces govern the change. Unaffected implementation bytes are reused.

## Choosing a foundation
- Power ON RK_example0: startup foundation, no Pinging business action.
- RK_example3: already includes ACK/WDG Pinging; use when that existing application is intended.
- Foundation: Power ON plus integrated periodic TMR mode/count, no active manual patch. Owner-scoped acceptance; all recorded exclusions remain.
Using the same pair for Example2 requires all missing behavior; using an Example1-derived pair requires only the remaining delta. Required drivers/contracts must exist. A missing foundation blocks this incremental exporter; it does not authorize invented hardware interfaces.
