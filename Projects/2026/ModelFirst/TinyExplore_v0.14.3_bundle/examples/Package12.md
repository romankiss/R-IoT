# Package12 · reusable foundations

Human task + selected trained package12 → reviewed complete package1 → Code-First → target evidence → accepted package12. A trained pair is an empirically validated reusable Model/Code context, not machine-learning weights or a universal correctness guarantee.

SYS, EMPTY and SYS+EMPTY templates illustrate deriving a module set from a supplied pair. Their ZIPs are Model-First examples, not newly runtime-verified pairs. No module is universally mandatory; required capabilities derive from the task and target.

Reusable human request: “Derive a complete standalone package1 containing [SYS | EMPTY | SYS + EMPTY] from the supplied pair. Remove excluded modules, bindings, composition and application actions. Preserve HAL separation, Metadata Connectors, supported contracts and unrelated golden bytes. Validate references/fingerprints, retain pair provenance and return package1 only.” Provide target identity/version and the actual baseline. The agent must ask for missing required inputs, not search other chats or repositories.

TMR Extension is a real module increment: periodic TMR followed by a mode/count overlay and reviewed integration into Foundation1.0.0. Yours Extension starts an editable package0 for your module task.

SYS+SENSORS and the dedicated Prepare module composer remain planned. Future module authoring produces README.md, _at.json and _module.json; no such authoring feature is claimed by this read-only release.
